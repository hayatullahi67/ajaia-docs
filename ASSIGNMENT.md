# Ajaia LLC – AI-Native Full Stack Product Engineer (take-home brief)

## Objective
Test how you handle a realistic product-engineering problem with ambiguous scope, multiple surfaces, and tight delivery constraints: how you prioritize, what you build, how you communicate tradeoffs, and how you use AI tools without outsourcing judgment.

Time limit: 4–6 hours. A focused, well-reasoned partial solution is better than an overextended build.

## Scenario
Build a lightweight collaborative document editor inspired by Google Docs. Not a full clone: ship the strongest working version within the timebox, showing product judgment, full stack capability, and clear prioritization.

## Tasks
1. **Document creation and editing**: create, rename, edit in browser, save and reopen. Rich text: bold, italic, underline, headings or text size, bulleted or numbered lists.
2. **File upload**: at least one product-relevant upload (e.g. .txt/.md/.docx into a new editable document, attachments, or import into an existing draft). State supported types in the UI and README.
3. **Sharing**: a document owner, a way to grant another user access, and a visible distinction between owned and shared documents. Seeded accounts or mocked auth are fine.
4. **Persistence**: documents and sharing survive refresh, formatting is preserved, shared access can be demonstrated.
5. **Product and engineering quality**: setup and run instructions, a working deployment, basic validation and error handling, at least one meaningful automated test, and a short architecture note explaining priorities.

## AI-native workflow note
Which AI tools you used, where AI sped you up, what AI output you changed or rejected, and how you verified correctness, UX quality and reliability.

## Walkthrough video (3–5 min)
Main user flow, what works end to end, what was deprioritized, key implementation decisions, and how AI supported the workflow. Unlisted Loom or YouTube link.

## Deliverables (one Google Drive folder)
- Source code
- README.md with local setup and run instructions
- Architecture note (Markdown or PDF)
- AI workflow note (Markdown or PDF)
- SUBMISSION.md listing exactly what is included
- Live product URL
- Text file with the walkthrough video URL
- Screenshots or a short demo GIF if setup needs extra steps

Also include any credentials or seeded users needed to test sharing. If anything is partial, state what works, what is incomplete, and what you would build next with another 2–4 hours.

## Constraints
- Keep the scope intentional; prefer depth in a few areas over shallow coverage.
- Any stack is fine; AI tools are allowed.
- Reviewers must not have to pay for any dependency or service.

## Evaluation
Coherent product slice; full stack execution (frontend, backend, persistence, access logic); editor quality; file upload and sharing; deployment judgment; code clarity and delivery discipline; prioritization and tradeoffs; communication; mature AI use.

## Optional stretch (only one, only if time allows)
Real-time collaboration indicators, commenting/suggestions, version history, export to PDF or Markdown, or richer role-based permissions.
